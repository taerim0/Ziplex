# AGENTS.md

This file provides guidance to AI coding agents (Claude Code, and any other tool following the AGENTS.md convention) working in this repository. `CLAUDE.md` at each of the paths below is just a one-line `@AGENTS.md` import, so Claude Code reads the identical content — see [`docs/team/agents-md.md`](docs/team/agents-md.md) for why, and what to do when adding a new directory-scoped doc. Kept intentionally lean (current-state map, not a change log) — see `docs/HISTORY.md` for the detailed decision/bug-fix history behind anything below. That file is never auto-loaded; open it only when the "why did we end up doing it this way" story actually matters for what you're about to change.

Directory-scoped detail lives in nested AGENTS.md files. Claude Code loads these automatically when you're working in that subtree (via each directory's own `CLAUDE.md` importing its sibling `AGENTS.md`); check your own tool's docs for whether it does the same:
- `src/ziplex/extract/code/AGENTS.md` — Tree-sitter code compression/extraction, one language per bullet (Python/Java/TypeScript/JavaScript/Lua/GDScript/Go/C++/Rust/C#/PHP/Ruby/Bash).
- `src/ziplex/extract/text/AGENTS.md` — the non-Tree-sitter text compressors (json/yaml/markdown/txt/dockerfile).
- `src/ziplex/file/AGENTS.md` — file collection, security scanning, and the dependency-graph API.
- `src/ziplex/gui/AGENTS.md` — the local GUI (Flask + pywebview backend, ES-module frontend).

Packaging: a real installable package (`pyproject.toml`, src-layout — `src/ziplex/` is the actual `ziplex` package). Internal imports are package-relative; nothing under `src/ziplex/` imports a sibling module by bare name. `pip install -e .` registers three console scripts: `ziplex`, `ziplex-gui`, `ziplex-mcp`.

## What this is

Local project → `aif.json`: a token-reduced context format an AI reads instead of raw files. Pipeline: Tree-sitter compression/extraction → Gemini summarization → optional human correction. `aif.json` carries only summaries + relationships, never full per-file code — shape at the bottom of this file.

## Commands

Setup (Windows, matches the existing `venv/` in this repo):
```
venv\Scripts\activate
pip install -e .                 # editable install: reads pyproject.toml, registers ziplex/ziplex-gui/ziplex-mcp
pip install -e ".[dev]"          # + pytest
```
`pip install -r requirement.txt` (no "s") is a lighter-weight alternative that skips packaging (no console scripts) — subcommands then run as `python src/cli.py ...`.

Requires a `.env` with `GEMINI_API_KEY=...` (via `python-dotenv`, `src/ziplex/llm.py`); optionally `GEMINI_MODEL=...` to override the default model.

Run any subcommand from repo root (`ziplex ...` after `pip install -e .`; `python src/cli.py ...` works either way):
```
ziplex pack <project_path>                              # full pipeline, interactive file selection + correction
ziplex pack <project_path> --auto                       # skip interactive selection, include all safe files
ziplex pack <project_path> --auto-correct                # skip interactive correction, auto-accept LLM output
ziplex pack <project_path> --auto --auto-correct         # non-interactive, for CI/scripted use
ziplex pack <project_path> --no-cache                   # force-resummarize every file
ziplex pack <project_path> -o out.json                  # custom output path (+ out.detail.json/out.cache.json)
ziplex pack <project_path> --include "src/**/*.py,*.md" --ignore "**/*.generated.*"  # one-off scope, on top of .ziplex.json
ziplex pack <project_path> --max-tokens 50000 --max-tokens-model GPT-4o  # CI guard: non-zero exit if payload exceeds N tokens
ziplex pack <project_path> --auto --no-llm               # no GEMINI_API_KEY/network -- structural summaries only
ziplex pack <project_path> --lang ko                     # packed CONTENT language (summaries/rules/AI guide) -- en (default) or ko

ziplex init <project_path>               # scaffold .ziplex.json (include/ignore patterns)
ziplex collect <project_path>            # just file collection + security scan
ziplex tokens <project_path>             # token count, before/after compression
ziplex tree <project_path>                # dependency tree only
ziplex search <project_path> <pattern> --context 2 --ignore-case
ziplex detail <name>.detail.json <file-key> --start 10 --end 40   # partial read of one file's compressed body
ziplex freshness <project_path> <name>.cache.json                # hash-check aif.json against disk, no LLM calls
ziplex skill <name>.json                                          # export as a Claude Agent Skill (.claude/skills/<slug>/)
ziplex signatures|dependencies|api|compress|debug <single_file>
```
(`<project_path>` is *any* target project being packed/inspected — `--include "src/**/*.py"` is that target project's own `src/`, unrelated to Ziplex's own.)

MCP server (exposes an already-packed project's `aif.json`/`detail.json`, read-only):
```
ziplex-mcp                                  # run directly, stdio transport
claude mcp add ziplex -- ziplex-mcp         # register with Claude Code
```

Local GUI (browse an already-packed project, or pack one interactively — see `src/ziplex/gui/AGENTS.md`):
```
ziplex-gui                                            # native window (pywebview)
ziplex-gui --aif out.json --project ./your-project    # prefill the landing page
ziplex-gui --no-window                                # plain browser tab instead of a pywebview window
```
`--auto --auto-correct` makes `pack` fully non-interactive: `checkpoint.py`'s `handle_llm_failure()`/`resume_checkpoint_choice()` both take an `interactive` flag (from `--auto-correct`) and skip straight to their non-interactive default (checkpoint-and-exit; always-resume) instead of calling `input()` against a closed stdin.

Tests (`tests/`, pytest via `pytest.ini` which puts `src/` on `pythonpath`):
```
pip install -r requirement-dev.txt   # or: pip install -e ".[dev]"
pytest
```
Covers the deterministic, non-LLM logic: compressors, extractor, `file/collector.py`'s filtering, `config.py`, `file/relationship.py`, `edits.py`, `search.py`, `freshness.py`, `confidence.py`, `skill_export.py`, `text_references.py`, `tech_stack.py`, `cli.py`'s argument-level wiring (via `monkeypatch`-injected fakes), `summarizer.py`, `tokenizer.py`, `checkpoint.py`'s non-interactive paths. `tests/test_pack_integration.py` runs the full `pack()` pipeline end to end against `llm.MockProvider`. `tests/test_mcp_server.py`/`test_pack_service.py`/`test_gui_server.py` cover the MCP and GUI layers on top of that. Nothing in the suite calls Gemini or needs `GEMINI_API_KEY`. `testfiles/` holds sample input for manual CLI runs, not part of the suite.

Manual smoke test against a real project without waiting on Gemini: `LLM_PROVIDER=mock ziplex pack <project_path> --auto --auto-correct` — network-free, under a second.

## Architecture

`cli.py` is a thin argparse dispatcher — all real logic lives in the modules it calls (including the `analyze` subcommand, a lighter-weight preview with no compression/relationships/tokens/saving, which delegates its own summarization to `summarizer.generate_summaries()` rather than a bespoke loop). `pack` runs the full pipeline end to end:

1. **`file/collector.py` → `file/scanner.py` → `file/selector.py`** — collect, security-scan, and (unless `--auto`) interactively select files. `collect_files()` takes optional `include`/`ignore` glob params (see `config.py` below) to scope collection before scanning/selection run. A recognized media asset (image/video/audio/font, `file/media.py`) survives collection despite being binary, always scans safe, and gets a free metadata-only `summary` in `pack()`'s per-file loop rather than reaching Tree-sitter/LLM. Detail: `src/ziplex/file/AGENTS.md`.
2. **`extract/code/*`** + **`extract/text/*`** — Tree-sitter signature/dependency/API extraction and body-stripping compression for code; structure-preserving compression for JSON/YAML/Markdown/plain text/Dockerfile. Detail: `src/ziplex/extract/code/AGENTS.md` / `src/ziplex/extract/text/AGENTS.md`.
3. **`tokenizer.py`** — counts tokens per model (`tiktoken`). `analyze_tokens_with_compression` (the `tokens` command) measures original vs. compressed body; `analyze_tokens_with_payload` (used by `pack`) measures original vs. just the per-file `summary` — the only per-file field that ships in `aif.json`. A media asset has no readable "original" (correctly 0 there) but its real `summary` is still counted on the payload side.
4. **`llm.py`** — three providers today (`GeminiProvider` default, `OpenAIProvider`, `ClaudeProvider`) + `MockProvider` for tests, behind `PROVIDERS`/`_active_provider()`. `GeminiProvider` calls Gemini's REST API directly (not the SDK). Model/key resolution is re-resolved fresh on every call, not cached at construction — explicit constructor arg → `settings.py` (GUI Options page) → env var → `GeminiProvider.DEFAULT_MODEL` (`gemini-flash-latest`, a floating alias; pin `GEMINI_MODEL`/the GUI's model field if you hit persistent 503s). Every Gemini request sends `generationConfig.thinkingConfig.thinkingBudget: 0` — none of this file's prompts (short, single-shot, "JSON only" extraction) need Gemini's extended "thinking" mode, and leaving it on bills real hidden output tokens. `analyze_batch_summaries(items)` bundles several files' signatures/dependencies (or truncated content) into one prompt/response, cutting request *count* (what drives 429/503) roughly by `summarizer.BATCH_SIZE`; `analyze_file_summary`/`analyze_text_summary` are the batch's per-file fallback. Every provider retries HTTP 429/5xx and transport-level failures (`requests.exceptions.RequestException`/`json.JSONDecodeError`) with backoff — `min(5*(attempt+1), MAX_RETRY_WAIT_SECONDS)` (50s cap), logged as a wait time plus a `[label]` prefix naming which file/batch/call is retrying, not an attempt counter — and carries an explicit `timeout=REQUEST_TIMEOUT` (60s), since `requests` has no default. Every `analyze_*()` function (except unused `analyze_relationships`) takes `lang: str = "en"` (`llm.LANGUAGE_NAMES`) and appends a one-line "write the value in {language}" instruction — the JSON *key* always stays English, the *value* follows `lang`. The three per-file summary prompts also carry `_IDENTIFIER_FIDELITY_NOTE` ("keep function/class/variable/file names exactly as written, don't translate them") — `confidence.py`'s word-overlap scoring can only find a match when the summary literally shares vocabulary with the source, which for non-English `lang` mostly only happens via an untranslated identifier. `analyze_prompt()`'s own instruction explicitly tells the model to focus on the project's purpose and not center the summary on the `rules` param's coding-style/naming conventions — see `packager.py`'s own bullet below for why `architecture` (its other input) needed a real data fix too, not just a wording one. `analyze_folder_summaries(folders, lang)` is the newest `analyze_*()` function — one call covering every folder in a project at once (see `folder_summary.py`'s own paragraph below).
   `OpenAIProvider` speaks the Chat Completions shape (works against real OpenAI, Ollama, LM Studio, vLLM, llama.cpp, OpenRouter, Groq — point `base_url`/`model`). `ClaudeProvider` is Anthropic's Messages API. `LLMProvider` (a `typing.Protocol`) is the seam for adding another provider — implement `generate(prompt, retry, label) -> str` and register it in `PROVIDERS`. `PROVIDERS["mock"]` (`MockProvider`) pattern-matches the JSON field name in a prompt's trailing example, network-free. Select the process-lifetime default via `LLM_PROVIDER=mock`/`openai`/`claude`; `settings.py`'s `resolve_llm_provider_name()` (the GUI Options page) wins over that when set, constructing a fresh provider instance per call so a switch takes effect on the very next pack.
5. **`checkpoint.py`** — `pack()`'s checkpoint/resume system, split out of `packager.py`. `handle_llm_failure()` lets a failing LLM call be retried, answered manually, or checkpointed to `checkpoint/<project_name>-<hash>.json` (hash = first 8 hex of sha256 of the resolved absolute path — prevents two different projects sharing a folder basename from colliding; safe to key on the raw path since this file is purely local/ephemeral, deleted on success, never committed the way `aif.json`/`detail.json`/`cache.json` are). `resume_checkpoint_choice()` is the matching question for a checkpoint found at a run's *start*. `pack(interactive=False)` skips every prompt either could raise, defaulting to checkpoint-and-exit / always-resume. `build_snapshot()` builds the `{project, rules, files_data}` dict, keyed by relative name; `pack()`'s `check_cancelled` reuses the same `build_snapshot()`/`save_checkpoint()` pair for a user-requested stop. `build_snapshot(lang=...)`/`unpack_snapshot()` also carry `project.language` — a resumed run's restored `rules`/`prompt`/per-file `summary` are only trusted when the checkpoint's own `lang` matches the resuming run's (`lang_matches`); a mismatch discards just that content, not the checkpoint's other data. A missing `lang` field defaults to `"en"`.
6. **`summarizer.py`** — `generate_summaries(pending, root, lang)` is `pack()`'s entry point when an LLM is available: batches `pending` into `BATCH_SIZE`-sized chunks (`chunked()`, by relative name), submits one future per chunk to a `MAX_WORKERS` thread pool. `request_batch_summaries()` falls back to per-name `request_summary()` for anything a batch response missed. `generate_structural_summaries(pending, root, lang)` is the `use_llm=False` counterpart — no network, each summary a deterministic one-liner from the file's own already-extracted `signatures`/`dependencies` (`_structural_summary()`), synchronous. `lang` feeds both `llm.py`'s prompts and `_STRUCTURAL_LABELS` (Ziplex's own fixed labels follow the chosen language too). `SUMMARY_FAILED_PLACEHOLDERS: dict[lang, str]` + `is_summary_failed_placeholder(summary)` (recognizes the placeholder in *any* supported language, since a cached previous-pack summary may be from a different `lang` than the one checking it) is the fallback for a failed summary. The per-file progress log prints `✅ <name>` for a real summary, `❌ <name> (...)` for a placeholder — never the same line for both.
7. **`packager.py`** (`pack()`) — orchestrates 1–6 plus `text_references.py` for non-code files and `folder_summary.py` for per-folder summaries: the pipeline stitcher, not owner of checkpointing or summary generation. `tech_stack` (`detect_tech_stack()`) is computed once, before rules/prompt, not just at final assembly — `_build_architecture_summary(rel_files_data, tech_stack)` feeds it plus every file's already-generated `summary` (capped at `MAX_ARCHITECTURE_FILES`) into `analyze_prompt()`'s `architecture` param, which used to always be `[]` (a dead parameter, never populated) -- the confirmed root cause of a real, reported problem: the AI guide reading like a coding-style blurb rather than a "what is this project" summary, since project_name plus a coding-rules list was *all* it ever had to work with. `use_cache=True` (default; `--no-cache` disables) auto-detects a previous successful pack at `RESULT_DIR` and reuses its `summary` for any file whose content hash still matches (`freshness.load_previous_summaries()`) — only `summary` is reused; `signatures`/`dependencies`/`api`/`compressed` are always freshly extracted (so a human's prior manual reparenting via `corrector.py`'s `move_file()` never rides along with stale dependency data), and `relationships` is always rebuilt from scratch. `use_cache=False` also discards a leftover checkpoint before it's ever unpacked (no interactive prompt either) -- `discard_checkpoint: bool | None = None` overrides just this half independent of `use_cache`: `None` (every CLI call, and the GUI's own fresh pack-form submission) keeps that behavior; an explicit `False` (only ever sent by the GUI's "다시 시도" retry button, see `gui/pack_service.py`'s `start_pack_job(resume=...)`) forces a leftover checkpoint to always resume regardless of what `use_cache` says -- without it, retrying a job that started with "완전히 재패킹" checked discarded the very checkpoint that same job's own failure had just saved, re-billing every file's summary on every retry. That forced resume still verifies the checkpoint's own restored file set is a subset of `preselected` before trusting it, unconditionally discarding it on a mismatch (never falling back to `not use_cache` there -- "does this checkpoint belong to me" and "should I trust my own summary cache" are independent questions, and a positively-identified mismatch must be discarded regardless of `use_cache`) -- checkpoints are keyed by project path only, never by which job produced them, so two overlapping pack attempts for the same project (a second tab, or a stale error screen retried after a different job already ran) could otherwise silently resume the wrong one's partial progress instead of failing safe. If a reused summary is a failure placeholder (any language), `pack(interactive=True)` asks once whether to regenerate those specific files (`_confirm_regenerate_failed_summaries()`); non-interactive callers leave it cached, since `confidence.py`'s forced `0.0` already flags it for review either way. `use_llm=False` (CLI `pack --no-llm`) skips every LLM call: summaries fall back to `generate_structural_summaries()`, `rules` stays `[]`, `prompt` becomes the fixed `STRUCTURAL_ONLY_NOTE[lang]` — a checkpoint's own restored `rules`/`prompt` are only honored when `use_llm and lang_matches` both hold, never partially. `check_cancelled` is `pack()`'s only way to be told to stop from outside its own thread — polled at three points (per-file during extraction, before the LLM summary step, right after it) via `_maybe_stop()`, which checkpoints before returning `{}` unless told to discard. Only meaningful for a caller running `pack()` on a background thread (the GUI); a synchronous CLI run leaves it unset. `result_dir` overrides where the `use_cache` lookup looks — not where *this* run's own output saves (`save_aif()`'s `output_path` handles that, separately). `lang: str = "en"` (CLI `--lang`, GUI dropdown) picks which language every LLM-written value — each file's `summary`, `rules`, `prompt` — is actually written in, independent of the GUI's own display-language switcher (`js/i18n.js`, which only ever translates the GUI's own chrome). Silently normalized to `"en"` for an unrecognized value. Recorded verbatim as `project.language`.
8. **`edits.py`** + **`file/relationship.py`** — the pure, I/O-free editing API (no `input()`/`print()`): field setters, `finalize_aif()` (builds `relationships`, prunes `signatures`/`dependencies`/`api`/`text_dependencies`), and the dependency-graph ops (`build_tree`/`move_file`/`has_cycle`). `pack_service.py`'s GUI review flow calls this directly; `corrector.py` is the terminal equivalent built on the same setters. `build_tree()` tags every `internal` edge reached *only* via `text_references.py`'s filename matching (never also a real import to the same target) as `internal_text_refs` — a subset of `internal`, not a separate edge list, so nothing that already reads `internal` needs to change. `get_dependents()`/`get_blast_radius()` take an `include_text_refs: bool = True` param (threaded through `query_service.py`, and from there through every MCP tool/GUI route built on them) for a caller that wants the weaker prose-mention signal excluded entirely rather than just flagged; `move_file`/`add_dependency`/`remove_dependency`/`remove_relationship` all keep `text_dependencies`/`internal_text_refs` in sync as edges are edited, and `add_dependency` upgrades an edge already present only as a text reference to fully certain the moment a human explicitly (re-)links it. Detail (especially `has_cycle`'s traversal direction — easy to get backwards): `src/ziplex/file/AGENTS.md`.
9. **`corrector.py`** — the thin interactive CLI wrapper around 8: walks the user through project name/guide/rules/summaries/folder summaries/reparenting, calling the matching pure function per accepted change. `--auto-correct` skips it entirely, calling `edits.finalize_aif()` directly. Per-file review is triaged by `confidence.triage()` — only files below `REVIEW_THRESHOLD` get prompted, each with its real extracted `signatures` (capped at 10, "+N more") shown alongside the summary. Per-folder review (via `edits.set_folder_summary()`) has no such triage — `folder_summary.py` carries no per-folder confidence signal, so every folder is prompted, same as `pack_service.py`'s GUI review screen.
10. **`packager.py`** (`save_aif()`) — splits `compressed` per file → `<name>.detail.json` (so the saved `aif.json` only ever carries `summary`) and the flat `_manifest` (a `{file: content hash}` map, see `freshness.py` below) → `<name>.cache.json`.

**`text_references.py`** extends `relationships` past code files, for free (no LLM call). A file with no Tree-sitter grammar always got `dependencies=[]` from `extract_dependencies()`. `find_text_references_for_file(file_path, name, all_names)` matches a non-code file's raw text against the *actual* collected-file list (full relative path, or bare filename+extension, both word-boundary anchored) — a bare stem alone is never matched (too much noise from common words). A match goes straight into that file's `dependencies`, same as a resolved import. `pack()` keeps matches in a side dict (`text_refs_by_path`) through the whole per-file loop and the LLM summary step, merging into `files_data[fp]["dependencies"]` only afterward — `summarizer`'s summary prompt switches from content-based to signature/dependency-based the moment `dependencies` is non-empty, so merging earlier would swap a text file's content-based prompt for a signatures-empty/dependencies-only one before it's ever actually summarized. Also wired into the standalone `tree` CLI subcommand. The same merge step also records the match separately as `files_data[fp]["text_dependencies"]` (a subset of `dependencies`, exact file names only) — this is what lets `build_tree()` tag a prose mention apart from a structural/import reference once both reach `relationships` (see `file/relationship.py`'s bullet below), closing what used to be a documented, permanent limitation here.

**`tech_stack.py`** — free (no LLM call), manifest-file-based fact block: `detect_tech_stack(root_path)` scans the project root's top level (not recursive) for known package-manager manifests (`package.json`/`requirements.txt`/`pyproject.toml`/`Cargo.toml`/`go.mod`/`Gemfile`/`composer.json`/`pom.xml`) and reads out each one's declared top-level dependency names (version specifiers stripped, capped at `MAX_DEPENDENCIES`, deduped). Attached unconditionally as `project.tech_stack` (`[]` if none found); `skill_export.py`'s `references/overview.md` renders it when present, and the GUI's Overview page renders it too. Deliberately shallow — no lockfile resolution, no transitive walking.

**`folder_summary.py`** — the aggregate-level counterpart to per-file summaries: one sentence per folder describing its role, attached as `aif["folders"] = {folder path: {"summary": ...}}`. `group_files_by_folder(files_data)` groups by each file's *immediate* parent directory (`Path(name).parent.as_posix()`, `"."` for a root-level file — not a special-cased sentinel). `generate_folder_summaries()` is a single batched LLM call covering every folder at once (a project's folder count is always far smaller than its file count, so this never needs `summarizer.py`'s own chunking/thread-pool machinery) — falls back to a free structural sentence (`"Contains N file(s): ..."`, capped list) per folder the response didn't cover, rather than a retry loop. `generate_structural_folder_summaries()` is the `use_llm=False` counterpart, same shape as `summarizer.generate_structural_summaries()`. Deliberately lighter-weight than rules/prompt/per-file summaries: a folder-summary failure is *not* wired into `checkpoint.handle_llm_failure()` at all (no checkpoint schema footprint for this). Correctable via `edits.set_folder_summary()` — surfaced in both `corrector.py`'s terminal flow and `pack_service.py`'s GUI review screen the same way per-file summaries are, but with no `confidence.triage()` equivalent of its own: every folder is always shown for review, never split into a flagged/auto-kept subset, since there's no per-folder confidence signal to triage on.

`cli.py`'s `pack --max-tokens N [--max-tokens-model MODEL]` is a CI-guard flag: after a normal pack completes, `_check_max_tokens()` (pure, testable without argparse) compares the chosen model's actual packed-payload token count against `N`; `main()` turns a failing/unknown-model result *or* a missing `aif` entirely (a checkpoint-and-exit, or a cancelled/empty run) into a non-zero exit — either way should fail a CI pipeline expecting a real, complete pack.

**`freshness.py`** sits outside the `pack` sequence but is also called by it: `check_freshness(file_paths, root, manifest)` re-hashes a project's current files and diffs them against a loaded manifest into a `FreshnessReport` (`changed`/`added`/`removed`/`unchanged`, plus `is_stale`), no Tree-sitter parsing, no LLM calls. `hash_file()` hashes a recognized media asset's raw bytes instead of decoded text. `freshness_candidate_files(scan_result, root, manifest)` is what every real caller passes as `file_paths`: unions `scan_result["safe"]` with any `scan_result["dangerous"]` entry whose relative key is already present in `manifest` — a file a human included anyway despite being flagged sensitive gets re-flagged as dangerous on every later scan regardless, so without this it would be reported as permanently `removed` even though it's unchanged and on disk; checked against the manifest specifically so a dangerous file that's genuinely never been packed doesn't flip to spurious `"added"` noise. `check_freshness_scoped(project_path, manifest)` wraps `collect_and_scan() → freshness_candidate_files() → check_freshness()` in one call — every real freshness caller (the `freshness` CLI subcommand, `query_service.check_freshness()`, `query_service._stale_warning()`, `gui/watcher.py`'s recompute) goes through this now rather than open-coding the sequence itself. `load_previous_summaries(root_path, selected, result_dir, lang)` is the actual staleness-stage-2 cache-reuse lookup `pack()` calls before deciding what's `pending`: returns `{}` outright (full cache miss) when the previous pack's own `project.language` doesn't match the requested `lang`, and requires at least `_MIN_OVERLAP_RATIO` (0.5) of the *current* file set to already appear in the previous manifest before trusting any of it (guards against two unrelated projects sharing a result-directory basename).

The `freshness` CLI subcommand exits 1 when `report.is_stale` — doubles as a free PR/CI gate (no LLM calls, no `GEMINI_API_KEY`) for a project that commits its Ziplex output (README's Team use section). Template: `docs/ci/freshness-gate.yml`.

**`search.py`** sits outside the `pack` sequence — pure query functions over an already-collected file set or an already-generated `detail.json`. `search_files()` regex-searches original file content, not `compressed` (a match inside a body-stripped function would otherwise be invisible). `read_detail_range()` slices a `detail.json` entry's `compressed` text by 1-based line range. Exposed via `search`/`detail` CLI subcommands and wrapped directly by the MCP server.

**`confidence.py`** — a free (no LLM call) heuristic for whether a summary is worth trusting: `estimate_confidence(summary, signatures)` tokenizes both (camelCase/snake_case-aware, single-suffix-"s" stemmed) and scores 0.0-1.0 by keyword overlap, capped at 3 matches so a file with many functions isn't penalized for a summary that abstracts over most of them. `1.0` when there are no signatures to check at all (text files) — **except** when `summary` is exactly a failure placeholder, forced to `0.0` regardless of signature count. `triage(files)` splits by `REVIEW_THRESHOLD` into (needs_review, auto_kept) for `corrector.py`'s per-file loop. Not a correctness guarantee — a summary using different (but accurate) words for the same idea scores exactly like a wrong one, and this can't tell the difference. Known, currently unresolved limitation: systematically under-scores non-English `lang` output even with `_IDENTIFIER_FIDELITY_NOTE` in place, since a good one-line summary is *supposed* to abstract away from literal identifier names — tracked as an open GitHub issue, not something a pure word-overlap heuristic can close without either an LLM re-verification call (breaks the "free" design) or a hand-maintained glossary that only ever covers generic vocabulary, not a project's own domain-specific terms.

**`query_service.py`** — the transport-agnostic read-query core `mcp_server.py` and `gui_server.py` both sit on top of. Nine functions (`get_overview`, `list_files`, `get_folders`, `get_relationships`, `get_dependents`, `get_blast_radius`, `get_detail`, `check_freshness`, `search_project`) over `edits`/`file/relationship`/`search`/`freshness`'s existing pure functions -- `get_folders` is the one exception reading a raw `aif.json` field directly (`aif.get("folders", {})`, `{}` for a project packed before the field existed) rather than wrapping a function from one of those modules, same shallow shape `list_files`'s own `files` read already has. Read-only by design — every function reads an already-packed `aif.json`/`detail.json`/`cache.json`, or (for `search_project`/`check_freshness`) re-collects and re-scans fresh from disk; none of them re-pack or re-correct a project. `get_dependents`/`get_blast_radius` are graph queries over the *human-corrected* `relationships` tree (`get_blast_radius` can legitimately include the queried file itself when it participates in an import cycle). `get_overview`/`list_files` take an optional `project_path` — when given, `_stale_warning()` (built on `check_freshness_scoped()`) adds a `"_stale"` key only if the pack has actually drifted.

**`config.py`** — an optional per-*target*-project `.ziplex.json` (in whatever project `pack` is pointed at, not Ziplex's own repo): `load_config()` never raises, falling back to `DEFAULT_CONFIG`. Scoped to just `include`/`ignore` glob-pattern lists. `pack()` loads it via `load_config(root_path)` and unions it with any CLI `--include`/`--ignore` — CLI flags augment the config file, never replace it. `pack_service.py`'s `list_selectable_files()` (GUI) loads the same config the same way. `init_config()` (the `init` CLI subcommand) scaffolds a starter file; idempotent.

**`settings.py`** — `config.py`'s per-*user* counterpart: one `~/.ziplex/settings.json` holding where the GUI's new-pack screen saves by default (a global `output_dir` plus per-project pins in `project_output_dirs`, a pin only ever written when a human types an explicit output path while packing that project) and every LLM provider's credentials/model (`gemini_api_key`/`gemini_model` and the `openai_*`/`claude_*`/`llm_provider` siblings). Resolved fresh on every LLM call, not cached — a key/model/provider switch in the GUI Options page has to take effect on the very next pack. `load_settings()` never raises. See `src/ziplex/gui/AGENTS.md` for the Options-page wiring.

**`skill_export.py`** — a third distribution channel alongside the MCP server and the GUI: `export_skill(aif_path)` turns an already-corrected `aif.json` (+ `detail.json`) into a Claude Agent Skill directory (`.claude/skills/<slugified project name>/` — `SKILL.md` plus `references/overview.md`/`files.md`/`relationships.md`/`detail.json`), which Claude Code progressively loads on its own with no server process running. Deliberately narrower than repomix's own `--skill-generate` — `references/files.md` stays to summaries + confidence (matching `aif.json` itself); the *compressed* (not raw) per-file body only ships as `references/detail.json`. Pure generation (`generate_skill_files(aif, detail)`) is split from the I/O wrapper. Exposed via the `skill` CLI subcommand.

**`mcp_server.py`** — registers `query_service`'s nine functions directly as `@mcp.tool()`s rather than wrapping them, so each tool's docstring (what the MCP SDK reads as its description) lives in exactly one place. Uses the official `mcp` SDK's `MCPServer` (`from mcp.server import MCPServer`; not the older `FastMCP`, which no longer exists in the installed SDK version). Run with `ziplex-mcp` (stdio transport).

**`src/ziplex/gui/`** (`gui_server.py`, `pack_service.py`, the static frontend) — a local GUI, for environments where Claude Code (or MCP generally) isn't available but browser-based AI chat is. Read-only browse routes sit on `query_service.py`; the `/api/select_files` + `/api/pack*` family runs `packager.pack()` itself, so a project can be packed from the GUI without a prior CLI run. Full detail: `src/ziplex/gui/AGENTS.md`. Run with `ziplex-gui [--aif PATH] [--project PATH] [--port 5321] [--no-window]`.

The final `aif.json` shape: `{ project: {name, prompt, tech_stack: [...], security_scan: {flagged, included_anyway, excluded}, format_notes, language}, rules: [...], folders: {folder-path: {summary}}, tokens: {...}, files: {name: {summary, confidence}}, relationships: {...} }`, with siblings `<name>.detail.json` shaped `{ file-name: {compressed}, ... }` and `<name>.cache.json` shaped `{ file-name: content-hash, ... }` (both flat, same file-name keys as `files` — not nested under a `files` key).

**`project.security_scan`/`project.format_notes`** — two small, free additions to `project`, both attached unconditionally, since `aif.json` is meant to survive outside any one tool session (committed to a repo, handed to a colleague, pasted cold into a web chat with none of Ziplex's own docs loaded alongside it). `security_scan` (`{flagged, included_anyway, excluded}`) is computed from `scan_files()`'s `dangerous` result intersected against the *final* `selected` list (not any CLI-only intermediate variable, so a GUI/`preselected` caller naming a dangerous file directly is still counted correctly); `{0, 0, 0}` when nothing was ever flagged. `format_notes` is a single fixed constant per language explaining the format itself to a cold reader: what `confidence`'s threshold means, and what `detail.json`'s `⋮----` marker stands for. `project.language` is the same "always attached, cheap fact" pattern applied to which language `prompt`/`rules`/every file's `summary` were actually written in.

Every LLM-facing function in `llm.py` follows the same contract: prompt says "JSON only, nothing else," caller does `json.loads()` and falls back to a default (`{}`, `[]`, `""`) on `JSONDecodeError` — callers in `packager.py` loop until they get a non-empty result or the user intervenes via `checkpoint.handle_llm_failure`.
