# src/ziplex/gui/ — local GUI (pack + browse), Flask + pywebview

Scoped notes for `gui_server.py`, `pack_service.py`, `watcher.py`, and the static frontend (`index.html`, the `js/` ES-module tree, `style.css`). See the root `CLAUDE.md` for how this fits into the overall pipeline. Detailed history (every real bug found in this GUI, the nav-guard modal's iterative rounds, accessibility fixes): `docs/HISTORY.md`.

This directory is the `ziplex.gui` subpackage, one level under the `ziplex` package root — every module it imports from there is reached via a relative import one level up (`from .. import query_service`). `gui_server.py` imports its own siblings via `from . import pack_service`. Run directly via the `ziplex-gui` console script or `python -m ziplex.gui.gui_server`.

## gui_server.py

The Flask app + CLI entrypoint. Two halves, split by read vs. write:

- **Read-only routes** (`/api/overview`, `/api/files`, `/api/folders`, `/api/relationships`, `/api/dependents`, `/api/blast_radius`, `/api/detail`, `/api/freshness`, `/api/search`) are thin adapters over `query_service.py` — the same core `mcp_server.py` sits on — translating query params to function calls and JSON responses. A human uses these pages to browse an already-packed project and copy what's useful (each page has a Copy button) into a separate web chat by hand.
- **The write path** (`/api/select_files`, `/api/pack`, `/api/pack/review`, `/api/pack/link`, `/api/pack/unlink`, `/api/pack/finalize`, `/api/pack/cancel`, `/api/pack/status`, plus `/api/relationships/link`/`/api/relationships/unlink`) runs `packager.pack()`/`pack_service.py`'s edit functions directly, so a project can be packed *and* have its relationships fixed after the fact from the GUI without a prior CLI run. `/api/pack/link`, `/api/pack/unlink`, `/api/relationships/link`, `/api/relationships/unlink` share one body (`_relationship_edit_route(id_field, result_key, fn)`) for parsing `{id_field, file, target}` and mapping `CycleError`/`ValueError` to 409/404.
- **`/api/settings`** (GET/POST) is a thin wrapper over `src/ziplex/settings.py`'s `load_settings()`/`save_settings()` for the Options page. POST merges a partial body onto whatever's already saved, never requiring the whole shape back.

Runs as a local Flask server wrapped in a native window via `pywebview` by default — `--no-window` (or a bare `flask run`/`app.run()`) drops to a plain browser tab. `static_folder="."` serves the frontend. Binds to `127.0.0.1` only, no `--host` flag — exposing this would open local project data (including original source, via `search_project`) to the network.

**Native OS dialogs**: the windowed branch exposes a `_Api` bridge (`js_api=...`) with `choose_folder()`, `choose_aif_file()` (OPEN, `.json`-filtered), and `choose_save_file()` (SAVE). `window.pywebview.api` only exists in the native window; `--no-window` mode falls back to a typed path. `_Api` is module-level (not nested inside `main()`), taking the lazily-imported `webview` module as a constructor argument so `--no-window` never needs to import the package at all.

**Native window-close guard**: `window.events.closing` is wired to `_confirm_close_if_reviewing(window)`, which checks `pack_service.has_reviewing_job()` and shows a native confirmation dialog if a job is mid-review — needed because `js/pack.js`'s own `beforeunload` guard only fires on a page reload/navigation, never on the native window's own close button (which tears the webview down directly, bypassing the DOM).

## pack_service.py

Background pack-job runner backing `gui_server.py`'s `/api/pack*` routes. `packager.pack()` is long-running (real LLM calls) and talks via `print()`/`input()` — wrong to run inside a Flask request handler — so this runs one pack per background thread and gives the routes something to poll: a job id, a `running`/`reviewing`/`finalizing`/`done`/`error` state, captured log lines, and a pause point for review.

- **`list_selectable_files(project_path)`** — runs `collect_files()`/`scan_files()` and returns the safe/dangerous split, since `file/selector.py`'s terminal picker reads from stdin, which doesn't exist over HTTP. `"dangerous"` entries carry `scan_file()`'s full reason/matched-line detail; `renderPackHome()`'s file-selection screen renders each as its own row with a normally-unchecked "include anyway" checkbox. Whatever's checked becomes `start_pack_job()`'s `selected_files`, feeding `pack()`'s `preselected` param. Also returns `default_output_path` (`settings.resolve_output_path()`) as a placeholder, not a filled-in value.
- **`start_pack_job()`'s output-path resolution**: a caller-given `output_path` (non-blank) pins the project to its parent folder going forward (`settings.set_project_output_dir()`). Left blank, it resolves through `settings.resolve_output_path()` instead (per-project pin, else the global default), or stays `None` (`packager.py`'s own `RESULT_DIR` default applies). Either way, the same folder is what `pack()`'s `result_dir` param gets too, so incremental-reuse cache lookup and the actual save destination never drift apart.
- **`start_pack_job()`** runs `pack(..., interactive=False, preselected=...)` — non-interactive so a repeated LLM failure can't block on stdin — but does **not** follow it with `finalize_aif()`. The job pauses in state `"reviewing"` with the raw `aif` attached, mirroring `corrector.py`'s `correct_aif()`: project name/prompt/rules, per-file summaries triaged by `confidence.triage()` into `needs_review` (shown with real `signatures`, capped at 10) vs. `auto_kept`, and every folder summary (untriaged — see the `folder_summary.py` bullet in the root `CLAUDE.md`). `no_llm` threads to `pack(..., use_llm=False)`; `lang` threads to `pack(..., lang=...)` — both validated/normalized before reaching here. `job["lang"]` is echoed back in `get_job_status()`'s `retry_params` so a checkpoint-resume retry reposts it verbatim.
- **`add_dependency_in_job()`/`remove_dependency_in_job()`** wrap `file/relationship.py`'s `add_dependency`/`remove_dependency` — a per-edge link/unlink pair, not `move_file()` (see that module's own docstring for why).
- **`submit_review()`** applies whatever the human changed through `edits.py`'s setters, then finalizes and saves. Folder summaries (`folder_summaries: dict[str, str]`) go through `edits.set_folder_summary()` the same way per-file `summaries` go through `set_file_summary()` — `_build_review()` lists every folder for editing (no `confidence.triage()` split; `folder_summary.py` has no per-folder confidence signal).
- **`get_review()`** recomputes `_build_review(job["aif"])` fresh on every call, never cached across calls.
- **`get_job_status()`'s `retry_params`** — always present, a straight echo of `start_pack_job()`'s own argument shape. Lets the pack-progress screen's error state repost the same request via a "다시 시도" button, letting `pack()`'s own checkpoint auto-resume pick up from exactly where it left off. `output_path` here is the *original* caller-given value (possibly blank), not `start_pack_job()`'s own resolved one — retrying a job that started blank must stay blank on retry too, or it would silently pin the project via `set_project_output_dir()`. `retry_params` itself never carries a `resume` key -- `js/pack.js`'s retry button adds `resume: true` on top of the spread `retry_params` when it reposts to `/api/pack`, since that flag describes *this specific request* (a resume-of-a-failure), not the original job's own settings.
- **`start_pack_job(..., resume=False)`** threads straight to `pack(..., discard_checkpoint=False if resume else None)` — see `packager.py`'s own `discard_checkpoint` bullet in the root `CLAUDE.md` for the full story. A real bug reported directly: a job started with `no_cache=True` ("완전히 재패킹" checked) that failed mid-way checkpoints its already-generated summaries same as any other job, but retrying it (which reposts that same `no_cache=True`) used to discard that checkpoint outright, since `use_cache=False` alone made `pack()` treat *any* leftover checkpoint as stale -- re-billing every file's summary on every single retry. `resume=True` is set only by the error screen's own retry button (never a fresh "패킹 시작" submission), so "완전히 재패킹" still discards a genuinely stale, unrelated checkpoint from an *older* abandoned run the normal way. `pack()`'s own forced-resume path additionally verifies the checkpoint's file set actually matches `selected_files` before trusting it (a code-review finding: checkpoints have no job identity of their own, so two overlapping jobs for the same project could otherwise cross-contaminate on retry) -- see the root `CLAUDE.md`'s `discard_checkpoint` bullet.
- **`request_cancel(job_id, save)`** — the "running"-state counterpart to `cancel_job()` (which only ever applies to a paused "reviewing" job). Sets `job["cancel_action"]`, which `_check_cancelled_for(job)` hands to `pack()` as its `check_cancelled` callback. `save=True` checkpoints wherever analysis has gotten to (the same `checkpoint.build_snapshot()`/`save_checkpoint()` pair `handle_llm_failure()` uses); `save=False` discards it. Not instant — the job keeps reporting `"running"` until `pack()` actually reaches its next checkpoint.
- **`link_saved_relationship()`/`unlink_saved_relationship()`** — the *post-pack* counterparts to `add_dependency_in_job`/`remove_dependency_in_job`, for a project already packed and saved (no live job, just an `aif_path` on disk). Wraps `file/relationship.py`'s `add_relationship()`/`remove_relationship()` — the `relationships`-shaped counterparts to `add_dependency()`/`remove_dependency()`, needed because `finalize_aif()` prunes each file's working-state `dependencies` once `relationships` is built. `_edit_saved_relationships(aif_path, edit)` reads aif.json, applies `edit(relationships)`, writes it back directly — not via `packager.save_aif()`, which expects the in-progress pack shape.

**Concurrency**: each job gets its own `threading.Lock` (`job["lock"]`), acquired for every read/mutation of that job's own fields — not one global lock for every job's fields. `submit_review()` moves a job into a transient `"finalizing"` state *before* its mutators would release `job["lock"]`. `has_reviewing_job()` follows the same discipline. `print()`-capturing (`_capture_for_job`/`_LogWriter`) is the one deliberate exception, serialized across *all* jobs via a single `_stdout_capture_lock` (`sys.stdout` is one process-wide global). The on-disk writes (`link_saved_relationship`/`unlink_saved_relationship`, `submit_review()`'s finalize-and-save) aren't jobs, so `job["lock"]` doesn't cover them — `_lock_for_path(path)` gives each resolved aif.json path its own lock (via `os.path.normcase()` on top of `Path.resolve()`, since `resolve()` alone only normalizes an *existing* file's case on Windows). `submit_review()` locks `packager.resolve_output_path(aif, output_path)` — the same path-fallback `save_aif()` itself uses, so a live job's finalize and a Relationships-page edit aimed at the same file can't race. `_file_locks` is bounded (`_evict_old_file_locks()`, mirroring `_MAX_FINISHED_JOBS`), only ever evicting an *unlocked* entry other than the one currently being requested.

Jobs live in memory only (module-level `_jobs` dict) — gone on server restart.

## watcher.py

Live filesystem watching backing `/api/watch/start`/`/api/watch/status` — makes the Overview/Files staleness badge update on its own while that page stays open, instead of only checking once at page-load. Built on `watchdog`'s `Observer` (OS-level notifications, not polling), so idle cost is effectively zero.

`start_watch(project_path, aif_path)` is idempotent — restarting a watch for a project already being watched stops the old `Observer` first. `MAX_WATCHERS` (5) bounds a long session's total watcher count by evicting the oldest. One watcher per project path (a `dict` keyed by resolved absolute path, its own `threading.Lock`).

Events are filtered before scheduling a recompute: `_build_ignore_spec()` builds the same `pathspec` `file/collector.py`'s `collect_files()` does; `_DebouncedHandler` checks a changed path against it first, purely to avoid an unnecessary recompute for `.git`/`node_modules`/`venv` churn. Debounced (`DEBOUNCE_SECONDS`, 1.0 default) on top of that — a burst of events (a save, a git checkout) collapses into at most one recompute after it goes quiet.

`start_watch()` runs `recompute()` once synchronously before returning, so the first `/api/watch/status` poll already has a real report instead of `None`.

**Frontend wiring** (`js/app.js`'s `startStaleWatch()`/`stopStaleWatch()`): called from `renderOverview()`/`renderFiles()` only. `startStaleWatch()` fires `/api/watch/start` then polls `/api/watch/status` every 3 seconds, calling `setStale()` only when a real report comes back — a `null` report (watcher not started yet, or evicted) leaves the page's own initial-load badge alone. `router.js`'s `route()` calls `stopStaleWatch()` unconditionally at the top of every navigation (the hash router has no per-page unmount hook otherwise), preventing a leaked `setInterval` per visit.

## Frontend (`index.html` / `js/*.js` / `style.css`)

No build step, real ES modules (native browser support via `<script type="module" src="js/router.js">`). State (`aif_path`/`project_path`) lives in `localStorage` — every `gui_server.py` route is stateless.

**Pages**: the topbar's four global destinations — bare-logo home (`renderHome`, `/`), pack-new-project (`renderPackHome`, `/pack`), open-existing-project (`renderCheck`, `/check`), options (`renderOptions`) — plus the sidebar's project-scoped sections once a project is loaded: overview, files, file detail, search, relationships (`renderRelationships`), and the pack job/review flow (`renderPackJob`).

**Module layout**: `js/i18n.js` (display-language dictionary/`t()`, no imports of its own), `js/app.js` (localStorage state, `api`/`apiPost`, `el`/`copyButton`/`showLoading`, native-picker buttons, `confidenceLevel`/`setStale`/`setActiveNav`/`setActiveTopbar`, `showConfirmModal`), `js/graph.js` (dependency-graph components), `js/pack.js` (`renderPackJob`), `js/pages/` (one file per destination — `landing.js` bundles `renderHome`/`renderPackHome`/`renderCheck`; `options.js`, `overview.js`, `files.js`, `relationships.js`, `search.js` each hold their own page), and `js/router.js` (`route()`, the `DOMContentLoaded`/`hashchange` bootstrap, the sole `<script>` tag `index.html` loads). Every user-facing string goes through `t()`; `getLang()`/`setLang()` persist to `localStorage` (`ziplex.lang`) and re-run `route()` on change — a purely client-side chrome-translation preference, unrelated to `packager.pack()`'s own `lang` param (see root `CLAUDE.md`).

**Sidebar** (`.sidebar`, fixed left, `#nav`'s id unchanged): a deliberate positioning choice for a single-user, `127.0.0.1`-only, natively-windowed app — reads as "a program on your machine," not a web dashboard. `setActiveNav(routeName)` highlights the current section, called once per navigation from `route()`.

**Topbar** (`#topbar`): a thin strip above `.shell`, present on every screen. Four destinations — the logo (`#/`), "프로젝트 패킹" (`#/pack`), "프로젝트 확인" (`#/check`), "옵션" (`#/options`) — checked before `route()`'s "no project loaded, bounce to `#/check`" guard, since none of them require a project already loaded.

**Sensitive-file review** (`renderPackHome`'s file-selection step): a flagged file renders its own row with `scan_file()`'s reason + matched line and a checkbox, unchecked by default, tracked in a *separate* `dangerousCheckboxes` array so the safe-files list's own "전체" (select-all) can never sweep one in by accident. A second, distinctly-styled select-all (`.select-all-row`/`.dangerous-select-all`) scoped only to the dangerous list is available for a deliberate one-click "include everything I've reviewed," two-way synced with the individual checkboxes. A plain-language line under the count explains what checking a box actually commits to (the file's original, unredacted content ships in `aif.json`). Checking one and packing sends its name in `selected_files` alongside the normal safe ones — `packager.pack()`'s `preselected` handling trusts either list equally.

**`overview.js`** renders `project.tech_stack` (already in the `/api/overview` payload — no route change needed) as its own "기술 스택"/"Tech Stack" section between the AI guide and Rules: one line per detected manifest (`language (manifest): dep, dep, ...`), skipped entirely when `tech_stack` is empty. The Copy button's `summaryText()` includes the same section.

**`files.js`** was a flat sortable table until a reported usability gap: a human browsing the GUI to understand a project had no sense of directory structure at all, and the AI guide (before the `analyze_prompt()`/`architecture` fix — see root `CLAUDE.md`'s `packager.py` bullet) read like a coding-style blurb rather than a project summary, compounding the problem. Redesigned as a collapsible folder tree (`buildFolderTree(files)` groups the flat `/api/files` map by path segment, one level at a time, mirroring `folder_summary.group_files_by_folder()`'s own per-file-immediate-parent grouping so the two trees agree on which folder owns which file) fetching `/api/folders` alongside `/api/files` and rendering each folder's own summary next to it (`<details class="tree-node">`/`<summary>`, reusing `graph.js`'s existing tree CSS classes rather than inventing new ones). The root's own key is `"."` (matching `folder_summary.py`'s convention), displayed as a translated placeholder (`files.rootFolder`) rather than a bare dot. The search filter still works the same way (substring match on filename/summary), now hiding a whole folder subtree when nothing under it matches rather than just a table row. Sortable name/confidence columns were dropped in the redesign — a per-file confidence badge (`confidenceLevel()`, same color convention as before) is still shown per file row for at-a-glance triage. Two new CSS classes support this without touching `graph.js`'s own shared `.tree-name`/`.tree-row` classes: `.tree-name-fixed` (a folder/file's own name never wraps, unlike the dependency tree's lone-name case) and `.tree-desc` (the trailing summary text is what wraps instead, via `flex: 1 1 auto; min-width: 0`).

**Options page** (`renderOptions`, `js/pages/options.js`): display language, an AI provider selector, and the global default output folder — three independent save actions. The provider selector (Gemini / OpenAI-compatible / Claude, mirroring `llm.py`'s `PROVIDERS` minus the test-only `"mock"`) toggles which field group is visible; one shared save button POSTs `llm_provider` alongside whichever group's fields are currently showing, so a key is never stored against a mismatched `llm_provider`. The OpenAI-compatible group's base-URL row has "Ollama defaults"/"LM Studio defaults" preset buttons, filling the field with each tool's well-known local port. `type="password"` on key fields masks visually only — `GET /api/settings` still echoes every real value back in plain JSON, same 127.0.0.1-only trust model as the rest of this GUI.

**Freshness badges** (`renderCheck`'s recent-projects list, and the top-of-page `staleBadge`): both are real `<button>`s (`aria-expanded`/`aria-controls`), toggling a detail panel as actual DOM on click/Enter/Space (`app.js`'s `renderStaleDetail()` — a summary line + one `<ul>` per category, capped at `STALE_DETAIL_CAP` (15) with a "+N more" line) rather than a hover-only `title` tooltip (`staleTooltip()` still exists as a hover bonus for mouse users). The recent-projects row itself has a giant `onclick` (`openProject()`), so both the badge and its detail panel call `e.stopPropagation()`.

**Dependency tree overview** (`renderDependencyTreeOverview`) is the default view wherever relationships are shown — a read-only, collapsible whole-tree render, roots-first, needs-review files marked with `⚠️`. Clicking a file's own row switches to `renderRelationshipEditor` for that file. `buildNode()` uses two sets: `ancestors` (per-branch, guards against a true cycle on the *current* root-to-here path) and a flatter `seen` (shared across the *whole* tree render, including the top-level root loop) — the first time a file is rendered anywhere, its subtree fully expands; every later reference (from any parent, or a second disconnected root) renders as a shallow "already shown" row instead of re-expanding, bounding total rendered nodes to the size of the graph regardless of how shared any one file is.

**Relationships page** (`renderRelationships`) is the post-pack counterpart of the same tree/editor pair, sourced from `/api/relationships` instead of a live job's `review.tree`, edited via `/api/relationships/link`/`/api/relationships/unlink`.

**Relationship editor** (`renderRelationshipEditor`) is master-detail: a searchable file list on the left, and on the right only the *selected* file's own relationships — a small SVG ego-graph (`renderMiniGraph`, dependents left/dependencies right, capped at `REL_GRAPH_MAX_NEIGHBORS` (6) per side) plus link/unlink controls. Clicking a neighbor node jumps the selection to it. Graph node labels show basename only, falling back to `parentDir/basename` only on a same-graph collision.

**In-app navigation guard during an active pack job** (`pack.js`'s `activeGuard`/`confirmLeaveActivePackJob()`/`hasActiveGuard()` + `router.js`'s click-delegation and `guardedRoute()`): `beforeunload` only catches a real page reload/tab close, never an in-app hash-link click or Back/Forward. `renderPackJob()` keeps a module-level `activeGuard` (`null | () => Promise<boolean>`) current as the job moves through its states, `null` once `"done"`/`"error"`. Leaving a `"running"` job always stops it (no "just leave it running" option) — `showConfirmModal()` (see below) offers save & stop / discard & stop / stay. Leaving a `"reviewing"` job (edits only live in page state until submitted) offers stay / leave-and-discard, sharing `discardReview()`/`confirmDiscardReview()` with the Cancel button. `router.js` installs a document-level, capture-phase click listener for `<a href="#...">` (always `preventDefault()`s while a guard is active, deciding the actual navigation once the modal resolves) plus a `hashchange` listener (`guardedRoute()`, tracking `lastHash`) for Back/Forward, which can't be `preventDefault()`'d after the fact — it reverts `location.hash` back to `lastHash` via `history.replaceState()` (not a plain assignment, which would push a spurious history entry) and re-applies the target only if confirmed. The re-entrant "settling" hashchange (`newHash === lastHash`) is a pure no-op — it must never re-invoke `route()`, since that would tear down and rebuild `renderPackJob()`, wiping any in-progress "reviewing" form edits.

**`app.js`'s `showConfirmModal(message, buttons)`**: an in-page, app-themed confirmation dialog (`.modal-overlay`/`.modal-box`) replacing `window.confirm()` everywhere in `pack.js`. `buttons` is `[{label, value, primary?}, ...]`; resolves to whichever button's `value` was clicked, or `null` if dismissed via backdrop/Escape. Only one modal is ever open at a time (`openModal`, module-level) — a second call while one's pending returns the same promise. `role="dialog"`/`aria-modal="true"`, focus moved to the primary button on open and restored on close, with a minimal Tab/Shift+Tab trap cycling only through the modal's own buttons. `pack.js` guards against re-entrancy separately (`pendingGuardDecision`) — a fast double Back-press or click gets the same in-flight promise rather than invoking `activeGuard()` twice.

The final `aif.json` shape and the LLM-facing-function JSON contract are documented at the bottom of the root `CLAUDE.md` — nothing GUI-specific about either.
