# src/ziplex/extract/text/ — non-Tree-sitter compressors

Scoped notes for `registry.py`/`json.py`/`yaml.py`/`markdown.py`/`txt.py`. See the root `CLAUDE.md` for how these fit into the overall `pack` pipeline, and `src/ziplex/extract/code/CLAUDE.md` for the sibling Tree-sitter-based code extraction/compression these fall back to when there's no grammar for a file's extension. Detailed history (the YAML corruption bug and its fixes): `docs/HISTORY.md`.

- **`registry.py`** — `TEXT_COMPRESSORS: dict[ext, Callable[[str], str]]`. `compress_file()` in `extract/code/compressor.py` falls back here when there's no Tree-sitter grammar for the extension. To support a new text format, write a `compress_*(text) -> str` function and register it here.
- **`json.py`** — parses and keeps structure (keys), eliding only long strings (`MAX_STRING_LEN`) and long arrays (`MAX_ARRAY_ITEMS`, keeps the leading items + a marker). Falls back to the original text unchanged if `json.loads()` fails.
- **`yaml.py`** — same idea as `json.py` (keep keys, elide long strings/arrays via the same thresholds) but built on `ruamel.yaml`'s round-trip mode (`preserve_quotes=True`, `width=4096`), not a parse-and-redump the way `json.py` is. YAML 1.1's implicit scalar typing makes a naive PyYAML parse-and-redump lossy (an unquoted `3.10` becomes the float `3.1`, `NO` becomes `False`) — round-trip mode keeps every untouched scalar's exact original text, preserves key order (PyYAML's `safe_dump` alphabetizes), preserves comments (PyYAML drops them), and keeps anchors/aliases (`&x`/`*x`) as references instead of expanding them (expansion would make an anchor-heavy file *larger*). `_compress_value()` mutates the loaded `CommentedMap`/`CommentedSeq` in place rather than rebuilding plain `dict`/`list` — ruamel attaches comments to the container instance itself, so a comprehension-rebuild silently drops them. A map merged via `<<: *anchor` has every merged key sitting in its own storage at load time, so a naive reassignment of an untouched value still makes ruamel treat that key as newly explicit and duplicate it alongside the `<<:` reference — `_compress_value()` reads each map's `.merge` attribute and skips any key already listed there. A plain `*alias` referencing a whole list/map (not a `<<:` merge) is the *same Python object* as its `&anchor`, not a copy — `_seen` (a `set()` of `id()`s, reset per top-level call, since an alias never crosses a `---` document boundary) guards against processing an already-visited container twice, which would otherwise double-truncate around the first pass's own marker string. Handles multi-document files (`---`-separated) via `load_all()`/compress-each/rejoin; a single-document file gets no leading separator. Falls back to the original text on a `YAMLError` or an empty/whitespace-only file. Registered for both `.yaml`/`.yml`. Uses `ruamel.yaml`, not `pyyaml`, per the corruption issue above.
- **`markdown.py`** — line-oriented regex approximation (no Markdown AST available). Headings/blank lines always kept as structure. Lists/tables/paragraphs get the same "keep the lead, elide the rest with a marker" treatment past their own thresholds (`MAX_LIST_ITEMS`, `MAX_TABLE_ROWS`, `MAX_PARAGRAPH_LEN`). Code fences with a language tag `extract/code` recognizes (`_FENCE_LANG_TO_EXT` — kept in sync with `languages.py`'s keys) get real structural compression via `compress_code()`; if still long after that, truncated by line count same as everything else. Untagged/unrecognized languages skip straight to line-count truncation.
- **`txt.py`** — no structure to preserve beyond blank-line paragraph breaks; just the two generic rules (long block elided past `MAX_BLOCK_LINES`, long line truncated past `MAX_LINE_LEN`) that `markdown.py`/`json.py` also use for their own "body" content.
- **Circular import note**: `extract/code/compressor.py` → `extract.text.registry` → `extract.text.markdown` → (for code blocks) `extract.code.compressor.compress_code` again. Both directions import the other module's function inside the function body, not at module top, specifically to break this cycle — don't "clean up" those into top-level imports.
