# src/ziplex/core/ — the graph engine (no LLM, no UI)

Everything that turns collected files into dependency edges. `tests/core/test_layering.py` enforces that importing `ziplex.core.graph` never pulls in the LLM layer, `packager`, the CLI/GUI/MCP, user settings or progress i18n -- keep it that way. The CLI's `index`/`deps`/`impact`/`path`, MCP v2 and the editor hook all sit on `api.py` (`docs/REVIEW-2026-10-14.md` §5).

**`index.py`** — `GraphIndex(project, db_path=None)`: the persistent graph at `<project>/.ziplex/index.db` (WAL, single writer via `BEGIN IMMEDIATE`, writes its own `.ziplex/.gitignore`; a disposable cache, rebuilt when `SCHEMA_VERSION` changes). Tables: `files` (stat, blake2b hash, kind code/text/media/binary/excluded, `is_test`, `flagged`), `imports` (raw dependency entry + line + `ctx` module/function/typing/main, from `extractor.extract_imports()`), `edges` (dst or external, kind import/text, line, ctx). `update(paths=None)`: stat diff → hash diff (files written within 2s of the previous update are re-hashed: same-size rewrites in one mtime tick) → re-parse changed code files → re-resolve. **Invalidation is coarse on purpose**: a file-set change, a resolver-context file change (`tsconfig*.json`, `jsconfig.json`, `package.json`, `pnpm-workspace.yaml`, `go.mod`, `.ziplex.json`), a scope/config change or a new Ziplex version re-resolves *every* stored raw import (no re-parse; django ~0.2s) and re-matches every text file's mentions (~1.6s); otherwise only changed files are resolved. `paths=` is a hint (editor hook): known paths are checked alone, an unknown one falls back to a full walk. Media classification matches `classify_media_file()` (a media extension that decodes as text is text). Flagged files keep import edges but never text-mention edges; `.ziplex.json` `exclude_flagged_from_graph` drops them. `relationships()` returns the `build_tree()` shape -- `tests/core/test_index.py` checks it equals `build_graph()` and that random add/remove/modify/context-edit sequences equal a fresh build (keep that property test passing). Measured: index == pack graph on hono/scrapy/django/python-sdk; django no-change update 0.86s, one file with a path hint 0.12s.

**`api.py`** — `Graph(project)`: read side over `GraphIndex` with an in-memory adjacency cached per index `generation`. `refresh(paths)`; `resolve(arg)` (relative/absolute/backslashed path or unique suffix; ambiguous/unknown → `ValueError` listing candidates); `dependents(files, depth, include_mentions)` (hops, with the import line at hop 1); `dependencies(files, external)`; `path(a, b)` (shortest import chain with lines); `impacted_tests(files | diff=)` (reverse BFS over import + implicit edges, shortest chain per test, `untested` changed code files, `run_all` triggers, ready-to-run commands); `overview(scope)` (`graph_summary()` over code files + unresolved relative imports). `render_*` produce the compact text the CLI, MCP and hook print. Prose mentions never count as dependents unless asked. Edge kinds in the adjacency: `import` (module-level), `lazy` (function-local, `extractor._import_context()`), `inert` (`if TYPE_CHECKING:`, TS `import type`, `__main__` guard -- dependencies, but skipped by `impacted_tests`), `implicit` (conftest / Go package), `package` (module -> enclosing `__init__.py`, impact only), `text`. `_impact_closure()` never continues over a `package` edge after a `lazy` one (a package member's import runs `__init__.py`, not the functions it defines). Measured on 99 held-out commits (click/flask/rich/pygments, `eval/t2_impacted_tests.py`): recall 0.976, 0.988 excluding pytest-runner imports; see `eval/README.md`.

**`testmap.py`** — `is_test_path()` follows each runner's default discovery: Python by file name only (`test_*.py`, `*_test.py`, `tests.py` -- a helper under `tests/` or Django's `django/test/` package is not a test), JS/TS by `.test.`/`.spec.` names or `__tests__/`, Go by `_test.go`, other languages also by `tests/`/`spec/`-like folders; `conftest.py` is support, not a test. `api.Graph` derives it on load (the stored column isn't trusted, so rule changes apply without a reindex), `implicit_dependencies()` (a Python test → every ancestor `conftest.py`; a `_test.go` file → its package's other `.go` files), `forces_run_all()` (build/config/lockfiles), `run_command()` (pytest / vitest-or-jest by root `package.json` / `go test ./dir`).

**`diff.py`** — `changed_files(project, spec)`: `worktree` (default: `git diff HEAD` + untracked), `staged`, or any rev/range; renames count as delete + add; paths outside the project are dropped; non-ASCII names unquoted (`core.quotepath=false`).

**`graph.py`** — the single producer of a file's edges. `GraphBuilder(root_path, file_paths)` builds the per-run resolution context once (import context + `TextRefIndex`); `code_dependencies(fp, raw=None)` resolves a file's imports (pass the extractor's `raw` list when the caller already parsed it), `text_references(fp)` matches a non-code file's prose mentions (callers skip media), `file_edges()` returns both merged as `(dependencies, text_dependencies)`. `pack()` (incl. security-flagged graph-only files) and `ziplex tree` (`build_graph()`) both use it. Text mentions are merged into `dependencies` at extraction time; anything that wants imports only — summary prompts, the structural summary, rule inference's `signatures_map` — reads `code_dependencies_of(entry)` (dependencies minus text_dependencies).

**`text_references.py`** extends `relationships` past code files, for free (no LLM call). Callers build one `TextRefIndex(all_names)` per run and pass `index=` per file (content is split once into path-like runs and looked up; hits still go through `_contains_token()`, so results equal the old per-name scan -- django 49s → 1.4s). A file with no Tree-sitter grammar always got `dependencies=[]` from `extract_dependencies()`. `find_text_references_for_file(file_path, name, all_names)` matches a non-code file's raw text against the *actual* collected-file list (full relative path, or bare filename+extension, both word-boundary anchored) — a bare stem alone is never matched (too much noise from common words), and a bare filename+extension match additionally requires that exactly one *other* collected file actually has that basename, skipping the match for all of them when 2+ files share it rather than guessing (a root-level file's own full relative path *is* its bare filename, so it still resolves correctly via the unaffected full-path match; only the ambiguous fan-out to *other*, differently-pathed same-basename files is suppressed). Matches are merged into `dependencies` at extraction time via `GraphBuilder`; summary prompts read `code_dependencies_of()` so a text file still gets a content-based prompt. `merge_text_references(dependencies, text_refs)` is the shared merge step both callers route through — folds the match into `dependencies` and returns it again separately as `text_dependencies` (a subset of `dependencies`, exact file names only), which is what lets `build_tree()` tag a prose mention apart from a structural/import reference once both reach `relationships` (see `file/relationship.py`'s bullet in `src/ziplex/file/AGENTS.md`).

**`go_packages.py`** — closes a different, Go-specific gap the same way `text_references.py` closes its own: `_go_dependency_handler` (`extract/code/languages.py`) only ever returns a Go import's raw path string, but that path names a *package* (typically a whole directory of files), not a single file the way every other supported language's imports resolve — `resolve_dependency()`'s file-stem matching has nothing to match it against, so an internal multi-package import used to always resolve as "external." `read_go_module_path(root_path)` reads go.mod's own `module` directive (root-level only, same scope limit `tech_stack.py`'s own manifest scan takes); `build_go_package_index(all_names)` groups every collected `.go` file by its own directory; `expand_go_dependencies(deps, self_name, module_path, index)` is the actual expansion algorithm — turns a package import into the concrete files that make it up. Real callers don't call those three directly: `resolve_go_context(root_path, all_names)` bundles the once-per-run `read_go_module_path`/`build_go_package_index` pair, and `expand_dependencies_for_file(file_path, name, deps, go_module_path, go_package_index)` wraps the per-file `.go`-extension gate around `expand_go_dependencies()` — both `packager.py`'s per-file loop and `cli.py`'s `tree` subcommand call just these two wrappers. Free (no LLM call), and zero-cost for a non-Go project (`read_go_module_path()` returns `None` the moment there's no go.mod, and `expand_dependencies_for_file()` passes every dep through untouched in that case).

**`ts_paths.py`** — the TS/JS counterpart: rewrites a tsconfig/jsconfig `paths` alias (`@/utils/x`) or `baseUrl`-relative bare specifier to the collected file it names, so `resolve_dependency()`'s exact-filename check matches it (before this, aliases went to the stem heuristic -- external, or a wrong same-named file). Config is JSONC (`_strip_jsonc()`); the nearest ancestor `tsconfig.json` (else `jsconfig.json`) governs a file; relative `extends` chains are followed, package `extends` skipped; `paths` targets resolve against the effective `baseUrl`, else the config declaring `paths` (tsc's own rules); longest-prefix key wins, substitutions tried in order, then `baseUrl`. Only a hit on an actually collected file rewrites; anything else passes through. `include`/`files`/project references aren't modeled. Also resolves monorepo workspace imports (`resolve_workspace_import()`): packages from the root `pnpm-workspace.yaml` or `package.json` `workspaces` (a `.` entry = the root itself, `!`/outside-root globs skipped, an unparseable glob never fails a pack); `exports` subpaths, one-`*` wildcards and condition objects/arrays, first target that is a collected file wins (so `types` → an uncommitted `dist/*.d.ts` falls through to `default` → `src/`); no `exports` → `module`/`main`/`types`/`index`. Aliases are tried before workspace packages, tsc's own order. Checked against independent regex ground truth: shadcn-ui/taxonomy 270/270, t3-oss/create-t3-turbo 111/111 (51 cross-package), 0 extra each.

**`py_imports.py`** — the Python counterpart: `_py_dependency_handler` emits each `from P import a, b` name as one `P::a`/`P::b` entry (`PY_FROM_IMPORT_SEP`; `import P` and `from P import *` stay plain `P`), and `rewrite_python_imports()` resolves every entry on its own: `P::a` → `P/a.py` if `a` is a submodule, else P's own file (`P.py`/`P/__init__.py`, so a re-exported symbol keeps its edge), else external `P`. Never decided across statements -- a file-wide "package already covered" rule dropped `from mcp.server import Server`'s `__init__` edge whenever the same file also imported a submodule. `ziplex dependencies` (pre-rewrite debug output) shows the raw `P::name` form. Absolute modules resolve against every ancestor folder of the importing file as a sys.path root (nearest first — `backend/` for `from app.core.config import ...`), then fall back to a *unique* collected file whose path ends with the module path (`_module_suffix_index()`: the src-layout case, `tests/` importing `ziplex.x` from `src/ziplex/x.py`); ambiguous → left for the stem heuristic. Relative imports reuse `_resolve_python_relative()`; a relative symbol import that resolves to no file (`from . import __version__`) becomes an edge to the package's `__init__.py`, never an external. Checked on fastapi/full-stack-fastapi-template: Python 28/79 → 70/79 edges vs. an `ast`-based ground truth (the other 9 come from files the scanner flags on quoted test passwords, excluded by `--auto`), 0 extra; Ziplex's self-pack gained 16 real test→module edges and lost 7 bogus `import pytest` → `pytest.ini` ones.

**`import_context.py`** — the one pair every per-file dependency loop calls: `resolve_import_context(root_path, all_names)` once per run (Go module + package index, TS path index -- `None` for a project with no TS/JS files -- and the file set for Python), then `expand_file_dependencies(file_path, name, deps, ctx)` per file. `packager.py`'s `pack()` and `cli.py`'s `tree` both go through it, so a new language's project-level resolution is wired into both or neither.
